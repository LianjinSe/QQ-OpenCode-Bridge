# 文档知识库（LlamaIndex）

知识库保存管理员明确导入的资料，也接受主人私聊任务中通过原生工具提交的方法笔记；
个人记忆继续使用原有 Mem0 链路。
普通聊天附件不会自动进入知识库，文档也不会自动转换为个人事实。

## 使用

在管理台的「知识库」页面新建资料库，填写名称和用途说明，再上传文档。
支持 `.md`、`.markdown`、`.txt` 和可提取文字的 PDF；文本支持 UTF-8 和 GB18030。
单份最大 10 MiB、100 万字符；PDF 最多 200 页，分段最多 2000 个。
扫描件需先 OCR；加密 PDF 需先解密。最多 30 个资料库、500 份未删除文档。

默认所有资料库仅主人私聊可检索。编辑资料库时可以明确选择桥接授权列表中的群聊，
开放后该群全部成员均可通过机器人检索。其他私聊用户不能读取主人资料；
主人在群中提问同样只读当前群获准使用的资料库。
第一版默认检索当前聊天可用的所有资料库，模型可用 library_id 限定一个库。

同一个库上传同名文件会建立新版本，内容相同则跳过重复导入。
新版本依次解析、分段、建立向量索引，全部成功后才切换；处理期间旧版继续可用。
失败的后台请求有限重试，最终失败可在页面重试；服务重启会恢复未完成导入。
旧版在切换后停止检索并异步清理原文件与向量，保留版本元数据。
删除文档／资料库会立即停止检索，后台重试清理原文件及索引。
删除不能撤回已发送的 QQ 回复或清除 OpenCode 已有的上下文与外部备份。

「检索测试」只检索，不创建聊天或生成回答。可查看命中的原文和来源，并预览解析结果、
下载当前可用版本原文件。资料内容以转义纯文本展示，不执行其中的 HTML 或脚本。
最近检索记录保留 7 天，页面最多显示 20 次；记录查询、片段 ID、任务 ID、模式与耗时，
不另存完整模型输出。任务详情中的原生工具结果也可用于核对引用。

QQ 中可以问「根据知识库，更新服务前需要做什么？」。助手按需使用：

| 工具 | 用途 |
| --- | --- |
| knowledge_list() | 查看当前真实聊天可用的资料库 |
| knowledge_search(query, library_id?) | 检索最多 5 个片段，返回出处与原文 |
| knowledge_read(id) | 再次核对当前仍可读的原文片段 |
| knowledge_write(library_id, filename, content 或 path) | 主人私聊中提交方法笔记，进入后台索引队列 |

`knowledge_list/search/read` 只读；`knowledge_write` 可向当前主人私聊可用的库提交文档，
提供 `content` 或本地文件 `path`，同名文件按现有规则建立新版本。
工具不能删除资料或更改资料可见范围，这些操作仍由 WebUI 管理。
答案按文件、版本、章节或页码引用；资料不足时应说明。
文档是参考内容，不能授予身份或操作权限，也不能单独证明外部操作成功。

人格要求写笔记前用 `knowledge_list` 核对目标库及开放群；私聊写入的内容仍继承该库
的可见范围。私人经历、个人资料和聊天原话只写未向群开放的库，任何库都不保存凭据。
没有合适的库或不能确认范围时，保留本轮文件并说明条件，不猜测库编号。
笔记区分已验证结果、参考步骤和失败记录，避免覆盖用途不同的同名文档。
以上是模型写作与选库约定，不代表后端新增了内容隐私识别或证据校验。

`knowledge_write` 返回成功表示请求已受理，文档可能仍在解析或索引。
按返回状态说明进度，确认新版本可检索后才报告已生效；旧版仍可检索不能证明新版已就绪。

## 部署

使用 `requirements.lock` 安装依赖，在 `.env` 设置 `KNOWLEDGE_ENABLED=true`。
需要已有 `SUPERADMIN_USER_ID`、`SILICONFLOW_API_KEY`、`MEMORY_DATABASE_URL`；
模型、接口、维度和重排开关复用对应 `MEMORY_*` 配置，客户端直连并验证 TLS。
知识索引绑定建立时的 Embedding 地址、模型、维度；不允许静默混用向量空间。
更改这些配置需要另做知识索引迁移，不影响 Mem0 已有集合。

```bash
.venv/bin/python deploy/provision_knowledge_tools.py
opencode reload
# 检查聊天、发送和记忆队列后，只重启桥接
systemctl restart qqbot.service
```

插件仅合并到机器人工作目录配置，保留现有模型、供应商、记忆插件和会话映射。
人格规则原稿在 `deploy/qq-persona.md`，按维护指引核对独立更改后同步运行文件。
Nginx 的管理台 server 块需允许 11 MiB 请求体；应用对单文件单独限制 10 MiB，
认证和其他 JSON 请求仍限制 64 KiB。无需修改共享 OpenCode、NapCat 等服务的启动方式。

## 数据、检索与权限

- `STATE_DB` 同目录 `knowledge/catalogue.sqlite3`：资料库、文档、版本、原文片段、
  FTS5 关键词索引、检索记录及 Embedding 绑定信息。
- `knowledge/raw/<版本 ID>.<扩展名>`：显式上传的原文件，目录 0700、文件 0600。
- `knowledge/tools.sock`、`knowledge/tools.token`：本地工具通道，均 0600。
- PostgreSQL 独立 schema `qq_knowledge`：LlamaIndex 向量表，与 Mem0 集合隔离。

LlamaIndex SentenceSplitter 保留页码／标题元数据，pgvector 提供向量检索；
Jieba 中文分词加 SQLite FTS5 BM25 提供关键词检索，保留配置名等完整标识符。
两路排名融合后可用现有 Qwen 重排。模型不可用时可返回明确标记的关键词降级结果；
重排失败则保留融合排名，不冒称已经重排。

WebUI 管理动作使用现有独立管理员登录和 CSRF；QQ 工具由活动任务及根／子会话关系
派生真实身份，不接受模型传入 QQ、群号、owner 或权限。检索先限定可见库的当前版本，
远程请求后重新检查权限与版本；读取片段也复查，已删除／替换的 ID 不再可读。
任务结束、取消或查不到归属时拒绝工具查询。

备份需要同时覆盖原文件、SQLite（含 WAL 一致性）和 PostgreSQL 知识 schema。
不要只备份向量，不要用知识库操作替代 `/forget`，两者删除范围不同。
