# 统一附件发送工具

`qq_send_files` 用于向本次 QQ 聊天提交图片、视频、文档和音频。模型准备实际文件后主动
调用工具，最终回复只写聊天正文。普通聊天不调用工具，也不输出内部标签或清单。

```json
{"files":[{"path":"报告.pdf"},{"path":"演示.mp4","kind":"video"}]}
```

每项必须有 `path`，可以提供 `name` 和 `kind`。相对路径以本轮交付目录解析；kind 默认
`auto`，按文件内容识别，支持 image、video、audio、file。显式选择的媒体类型必须符合
内容，file 可将媒体作为普通附件。图片、视频、音频分别使用 image、video、record 消息段；
其他文件调用私聊／群文件接口。可播放格式和转码能力取决于当前 NapCat／QQ 环境。
宿主机需要 `file` 命令；识别不可用或内容未识别时，auto 按普通文件处理。

## 状态与恢复

- `queued` 表示已保存独立文件快照并记录提交回执，尚未发送。模型只能说明准备完成。
- 同一任务、会话及工具调用编号重试返回原回执，原文件后来被修改或删除也不重建快照。
- 同一任务重复的内容、名称和发送类型去重；不同调用累计受附件数量和字节数限制。
- 任务成功结束后附件进入原有持久化发送队列，附件全部确认成功后才发送最终正文；完成后不自动戳发起人。
- 附件交付成功后只发送模型原本的正文，不额外追加固定成功提示或文件名列表。
- 执行失败或取消不发送已提交的文件。仅缓存上传中断可重试；实际发送结果不确定时不盲目重发。
- 即时模式：模型调用 `qq_send_files` 后附件立刻进入发送队列，正文仍等任务结束；
  失败或取消时不补发尚未发出的附件。`DELIVERY_IMMEDIATE=false` 可退回旧的“任务结束后统一交付”。
- 即时出站去重键包含根任务、工具调用请求编号及该次文件序号，同一任务的多次提交互不覆盖；
  同一次调用重放及重复内容仍去重。修复不会自动补发历史中遗漏或已经失效的文件。
- 历史中的 `qq-delivery` 标记只隐藏，不再用于发送附件；已有出站队列继续恢复。

## 身份与范围

工具参数不接受用户号、群号或任务编号，真实身份从活动根／子会话绑定派生。所有已准入
任务可提交本轮交付目录、输入附件目录中的文件；同一私聊已提交插话的输入附件也可用。
其他任务、排队但未提交的插话、任意宿主机文件和符号链接均不能回传。普通群成员生成、
编辑文件仍需原有管理员审批；工具本身不开放任意文件写入或通用 NapCat 管理操作。

## 安装与维护

桥接启动时提供本地工具服务。`STATE_DB` 同目录的 `delivery-tools/` 保存 socket、认证
文件和 `requests.sqlite3`；目录 0700、文件和 socket 0600。快照位于 `.qq-outbound/任务编号/`，
每个调用使用独立目录，防止后续提交覆盖。上述运行数据不提交 Git。

```bash
.venv/bin/python deploy/provision_delivery_tools.py
opencode reload
systemctl restart qqbot.service
```

部署前按维护指引检查队列和活动会话；脚本仅合并此插件，保留已有供应商、插件及会话。
附件交付和生图规则集中在 `deploy/qq-persona.md`，同步到运行时 `AGENTS.md`。
不再逐轮写入 `qq-bridge.delivery`；复用已有根／群子会话时删除遗留指令。
已有本轮文件路径时，模型直接调用 `qq_send_files`，不必查询目录或发送限制。
仅需确定新文件输出目录时，才调用一次只读 `qq_delivery_context`，按当前真实活动任务取得 `output_dir`、
`input_dir`、已提交私聊插话的 `steer_input_dirs`、累计限制、发送模式和生图启用／超时信息。
该查询沿用根／子会话身份解析，不接受模型传入任务或收件人，不修改任务或发送队列。

生图脚本原稿在 `deploy/workspace-tools/imagegen.py`，使用以下方式安装；先确认运行人格
没有独立变更再同步，保留工作目录中的其他工具：

```bash
.venv/bin/python deploy/configure.py --workdir "$HOME/qq-agent-workspace"
```

调用 `tools/bridge-python tools/imagegen.py --help`（在专用工作目录运行） 查看参数。生图脚本复用原客户端，
默认从当前安装源码目录的 `.env` 和环境变量读取配置，按需支持 `--env-file`；凭据只在程序内读取。
通过 `--output-dir`、`--input-dir` 使用本轮查询结果，生成文件再由 `qq_send_files` 提交。
不为安装或重载清空聊天映射。
