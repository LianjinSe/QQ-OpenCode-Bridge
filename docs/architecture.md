# 架构与依赖边界

项目保持单进程模块化架构。QQ 普通执行任务继续串行，管理台、记忆和知识索引可以并发工作；
并发不改变真实身份、审批、会话隔离和持久化恢复规则。

## 装配与业务职责

`Bridge` 负责装配组件、连接任务通知和管理运行生命周期。组件显式接收需要的配置、
存储、客户端或回调，不保存整个 `Bridge`，也不通过通用依赖容器访问任意其他组件。
构造参数较多时使用具名参数，使依赖关系可以直接从装配代码中阅读。

群聊每轮身份指令只传机器人 QQ、真实发送者 QQ、当前群号和发送者身份类别。
审批与回复规则、群背景使用约定集中在运行人格 `AGENTS.md`，群聊正文只组装实际背景、
发起人信息和本次要求。模型提示不授予权限：`permissions_for`、本轮审批、原生工具身份与
可见范围校验继续由后端执行，群共享子会话在切换发起人时同步真实身份和基础权限。

| 边界 | 职责 |
| --- | --- |
| `router` / `commands` | 消息准入、任务入口和明确控制请求 |
| `conversation` | 使用冻结输入与群背景组装提交文本 |
| `runner` | 执行、交互、取消、完成判定和交付准备的协调 |
| `sender` | 从持久化 outbox 发送，处理确认、失败和不确定结果 |
| `tool_identity` | 从活动根任务和子会话解析真实任务身份，并在异步查询后复查 |
| `memory` / `memory_service` | 个人记忆协调、写入证据验证、更新和遗忘规则 |
| `memory_api` / `memory_backend` | 结构化模型 HTTP 请求和 Mem0 适配 |
| `memory_policy` / `content_safety` | 记忆召回规则与共享内容脱敏，不依赖业务服务 |
| `knowledge` / `knowledge_backend` | 文档版本、导入、检索和向量后端适配 |
| `*_tools` | 本地工具认证、参数、身份和返回格式；业务规则委托对应服务 |
| `webui_data` / `webui` | 只读查询与经过认证的显式管理操作 |

## 持久化与状态

业务模块使用 Store 的语义操作，不能取得 `store.db` 自行拼 SQL 或提交事务。
桥接、记忆、知识库仍各自拥有原有 SQLite 数据与索引，重构不改变数据库归属。
管理台的只读查询连接与写入 Store 分开；只读页面不能构造写入 Store。

任务状态及合法运行时转换集中在 `job_state.py`。运行流程通过状态转换接口更新任务；
迁移、故障恢复与测试准备需要显式区分，不能为了绕过转换检查回到任意状态写入。
任务完成与对应出站消息入队保持同一个 SQLite 事务。不能把这两步拆成仅在内存中传递的事件。

桥接与记忆之间的归档仍按持久化标志补偿恢复。文件快照、提交文本、提交 ID、进度游标、
插话来源与原任务绑定继续保留，重试不能重建输入或重复发送。

直接引用的图片、视频、音频／语音和文件先校验原消息范围，再作为任务附件保存，
随正文通过 file: URI 提交 OpenCode；附带文字保留为普通引用文字，不生成 JSON 聊天记录。
直接引用分享卡片时，提取有效网页链接与本次要求拼接进正文，沿用入队及提交文本冻结机制；
不生成聊天记录附件或自动抓取网页，转发内部的分享卡片仍保留在记录中。
纯文字及合并转发的记录保存为“引用聊天记录.json”附件，正文自然说明附件内容并附上本次要求。
生成的 JSON 文本作为附件快照随任务在同一入队事务中保存，准备阶段原子写入本任务输入目录，
使用 0600 权限，计入附件限制并复用已有文件；恢复不重新读取 QQ 原消息或展开转发。
转发内部媒体沿用原有处理。

## 原生工具与通信

各原生工具复用活动任务身份解析，再追加自己的权限规则。记忆所有者、管理员、当前群、
知识库可见性和附件交付目标分别检查，不能将某种权限当成所有工具的通行证。
发生网络或文件异步读取后，应在返回私密结果或产生写入之前复查相应的任务与资料状态。

OneBot 的公开流式请求接口拥有请求注册、接收和退出清理。NapCat 能力层只负责接口参数、
权限、分块内容与累计限制，不访问客户端的 `_send` 或 `requests` 内部字典。
不确定回执不能当作未发送，重构不得新增自动重发路径。

## 生命周期与管理台

生产入口先构造 `Store(initialize=False)`，再显式调用 `initialize()` 完成迁移与恢复。
初始化在同一实例上只执行一次；兼容的 `Store(path)` 仍会自动初始化，因此只读查询
仍不能构造 Store。组件装配失败时清理已打开的存储，退出时尝试关闭全部组件，即使
其中一个关闭失败也继续释放其余资源。

后台主任务仍采用 TaskGroup 的整体退出策略：未处理的内部异常会停止同组任务，由
systemd 按部署配置恢复。预期的连接失败、模型暂不可用和索引失败由对应业务已有的
重试或降级处理。不能吞掉未知错误让服务表面在线，也不自动重放结果不确定的外部操作。

管理台入口为 `console.html`，`console.js` 负责认证、导航和公共交互；
`console-conversations.js` 与 `console-knowledge.js` 各自拥有页面状态、加载、刷新和事件。
页面退出会使未完成查询失效，分页和搜索结果须核对所属会话或资料库后才能写回页面。
这些文件使用原生 ES modules，仍由同源静态资源白名单提供，不新增前端框架或外部脚本。

知识笔记只允许真实管理员私聊写入。读取本地笔记使用线程和大小上限，避免阻塞事件循环，
并在提交索引前复查身份及目标库；提交成功仍不等于索引完成。

## 验证边界

`tests/test_architecture.py` 检查本地模块依赖环、业务越过 Store 连接边界和组件重新持有
整个 Bridge 的情况。它补充现有行为测试，不替代取消、恢复、权限、交付或浏览器验证。

原生工具使用独立模拟服务或独立 OpenCode 加本地假模型验证。管理台前端改动还需验证
真实浏览器中的模块加载、页面切换、分页、滚动位置、刷新和手机导航。测试不得向真实 QQ
用户发送消息，也不得将生产认证信息放入测试输出。
