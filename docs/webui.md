# 助手管理台

管理台直接运行在 `qqbot.service` 中，复用现有 aiohttp，不需要 Node.js 构建或另一套模型服务。默认在 `http://127.0.0.1:8093` 使用；`https://bot.example.com` 仅为自有域名占位示例。

界面参考项目所有者的主页和 LumaGlass 博客，采用固定浅色蓝灰玻璃主题，不提供亮暗切换。中文宋体、英文等宽字体和薄雾 SVG 在管理台本地提供，不请求外部字体服务；字体许可随静态资源保留。

管理台样式及页面交互限定在 `#qqbot-console` 容器，避免影响浏览器插件和油猴浮层。为兼容 TimeHooker 等脚本的浮层，CSP 允许内联样式；脚本仍限定为本站来源，登录和 CSRF 校验不变。登录页采用左宽右窄的紧凑布局，在常见桌面视口内完整显示表单；手机和极矮窗口允许自然滚动。

站点图标和管理员头像使用通用 `favicon.svg`，助手头像使用新建通用图形，保存在 `webui_static/assistant-avatar.svg`；其他 QQ 用户显示通用用户图标，群聊显示群组图标。界面图标使用本地 Lucide SVG，许可证随静态资源提供，SVG 明确指定宽高和 viewBox。头像仅用于展示，不作为操作权限依据。
两张公开图片使用带内容版本的 URL 并缓存一天，避免聊天刷新反复下载；替换图片时同步更新 HTML 和 JS 中的版本参数。会话、认证及其他管理数据继续使用 `no-store`。

桌面侧栏可在宽、窄两种状态间切换，选择保存在当前浏览器的 `qqbot-sidebar-collapsed` 本地存储项；手机使用独立的抽屉导航，保留完整标签。顶部“控制台／概览”栏仅在概览页显示，其他页面在标题旁保留导航、刷新和账号入口。

## 登录

启用后首次启动自动创建独立管理员 `admin`。随机初始密码只写入 `STATE_DB` 同目录的 `webui-login.txt`，权限 0600，不在日志或接口中返回。项目所有者可在 Codex 文件面板打开该文件，无须 SSH。

登录后从右上角账号按钮设置自己的账号和密码。新密码至少 12 个字符；修改后初始密码文件删除，其他浏览器的登录失效。登录 Cookie 为 HttpOnly、SameSite=Strict；HTTPS 配置下启用 Secure。登录状态有效期 7 天，正常重启桥接不会清除登录。

认证档案保存在同目录的 `webui-auth.json`，包含加盐 scrypt 密码哈希、会话令牌哈希、少量管理操作记录及显式切换过的会话索引，权限 0600。它不能提交 Git，也不能通过静态文件路由下载。HTTP 修改操作还校验来源与 CSRF Token。
分支创建的最小请求回执与来源关系也保存在该档案中，不保存聊天正文；用于防止重复创建及发现尚未产生 QQ 任务的分支。

## 页面与能力

- **概览**：QQ／NapCat、OpenCode、个人记忆和知识库的连接状态，以及任务、发送异常和后台工作概况。知识库区分未启用、待就绪、已连接及暂不可用；只读检查资料目录与 PostgreSQL，数据库探测缓存 30 秒，不调用模型或创建索引。
- **会话**：按 QQ 私聊和群聊查找聊天，以左侧用户、右侧助手的气泡展示；私聊补充消息保留真实来源并单独展示。打开或切换聊天时定位最新消息，记录仍按正常时间顺序排列。聊天区独立滚动，加载旧记录保留阅读位置；自动刷新不会把正在查看旧记录的用户拉回底部，可用“最新消息”返回末尾。支持搜索原话及加载更早任务，无须消息 ID。历史任务保留各自原有 OpenCode 会话，不随当前映射改变。
- **执行详情**：按冻结的原始提交 ID 找到本轮记录，包含已提交插话，截止于下一独立用户轮次。展示 OpenCode 正文、工具输入输出、错误、模型返回的思考记录、用量、交付状态及诊断轨迹。
- **会话映射**：合并桥接数据库中的历史会话、映射切换索引，以及 OpenCode 中带桥接标记的根会话；包括已归档、`/new` 前和主人群聊独立会话。原始消息和子会话可单独打开并分页读取。OpenCode 索引不可用时明确提示当前只有本地记录。
- **任务队列**：查看待处理及历史任务，请求取消单个任务和其插话。取消沿用现有执行与发送状态规则，已发送消息不撤回。
- **记忆库**：以统一列宽、自然内容高度的错落瀑布流展示卡片，手机使用单列。查看当前机器人和记忆主人的档案，按内容、主体、类型筛选，展开未被抑制的来源原话。显示保护、私聊／群聊范围、待写入及短期状态过期标记；不展示已经遗忘的条目。当前为查询界面，记忆变更仍由现有记忆工具和 QQ 指令执行。
- **知识库**：新建资料库及编辑用途和群聊可见范围，上传 Markdown／TXT／文字型 PDF；查看导入状态、版本和失败原因，预览解析正文、下载原文件、重试或删除。检索测试只查询资料，不创建聊天；最近资料检索可追溯到实际任务。详情见 [知识库说明](knowledge.md)。
- **系统管理**：查看非敏感运行配置、管理账号、请求重启桥接并观察新的启动标识。运行配置当前只读。

“完整会话”表示读取 OpenCode 当前仍保留的原始记录，不会恢复已经在 OpenCode 中删除的消息。群背景仍遵循已有有限保留窗口。管理台不把完整工具日志和 reasoning 另行持久化到桥接数据库。

## 耗时和用量的含义

本轮统计只包含该轮主会话，插话共用统计。子任务会话单独查看，避免把历史上复用的子会话全部计入本次任务。

- 工具次数按实际工具内容块统计，展开可见名称、状态、参数、结果及时间戳。
- 思考耗时累加 reasoning 内容块已经记录的开始、结束时间。缺少时间戳时显示“未记录”，部分缺失则说明只统计了已记录部分。它表示记录时长，不能保证等于模型内部全部思考的计算时长。
- 响应轮次耗时按 assistant 消息开始、结束时间统计，可能包含该轮工具执行，不等同于纯模型计算时间。
- 执行计时沿用桥接 `elapsed`，等待授权／回答的暂停计时规则不变。
- Token 使用 OpenCode 返回的输入、输出、思考、缓存读取字段；不据此宣称真实账单金额。
- 完整会话的统计对应当前最近读取的一页，继续加载旧消息不把它冒充全历史总量；单个任务的执行详情会向前分页找到该轮原始提交再统计。

## 上下文用量与压缩

聊天顶部的上下文卡片对应这个 QQ 聊天的**当前映射**；尚未建立映射时不显示旧会话用量。
点击“完整会话”可以查看所选历史会话及子会话各自的用量和压缩状态。
上下文卡片独立刷新，读取更早历史不会改变它的统计口径。

占用估算使用 OpenCode 当前有效上下文中最近一次成功返回用量的 assistant 消息，
计算输入 + 缓存读取 + 缓存写入 + 输出 + 思考 Token，除以运行时所选模型的 `limit.context`。
这只代表最近一次调用结束时的测量，尚未计入后续新消息、工具结果或指令变化；
模型发生变化时会注明用量来自之前的模型。它不是历史累计消耗，也不表示自动压缩阈值。
缺少模型窗口时显示“上限未知”，缺少有效用量或刚压缩完成时显示“等待新用量”，不会伪造 0%。
查询只读取 OpenCode，不创建模型任务；卡片随管理台刷新，也可手动刷新。

“压缩上下文”经确认后调用 OpenCode v2 的 `POST /api/session/{sessionID}/compact`，
会请求模型生成摘要，可能产生 API 费用及丢失细节；原始消息仍保存在 OpenCode 中。
接口 HTTP 202 只表示已受理，后续根据 inbox 及 compaction 消息显示排队、执行、完成或失败。
网络超时或回执异常显示结果未确认，不自动再次发起；同一次操作保留请求编号用于幂等。
当前 OpenCode 缺少接口时明确显示不支持。接口约定见 [OpenCode 压缩说明](https://dev.opencode.ai/v2/docs/compaction/)。

压缩限已登录的管理台管理员操作，校验 CSRF 和桥接会话归属。
聊天有未完成任务、目标根会话及其子任务仍在执行，或目标会话已有待处理请求时拒绝压缩，
网络检查后再次核对本地任务。压缩只作用于所选会话，不切换映射、清空队列或发送 QQ 消息。

## 切换会话映射

可在“会话”页选择“切换分支”，或进入“会话映射”选择“切换映射”，选择同一聊天中可复用的原会话、历史会话或分支后确认。会话页操作后保留在当前聊天。

切换要求原聊天没有未完成的准备、执行、授权、回答或交付任务，原会话和目标会话的执行树也必须空闲。请求携带旧映射用于检查页面是否过期；网络检查结束后再次检查本地任务及映射，再同步更新。

不能切到另一私聊／群聊，不能把主人的私密群聊独立会话接入群共享历史。群共享映射切换以单次事务推进会话代次和背景游标。旧 OpenCode 会话、任务、原始归档和记忆保留；只影响之后的新任务。后续任务仍按真实 QQ 发起人设置权限，不继承旧任务的管理员身份。

## 创建会话分支

在“会话”页的当前聊天顶部点击“创建分支并切换”，可填写分支名称后确认。
后端调用 OpenCode v2 的 `POST /api/session/{sessionID}/fork`，不指定 `before`，复制完整历史。
完整会话中的用户及助手消息提供“从此消息前创建分支”，只复制所选消息之前的历史，不包含该条消息。
起点由服务端核实所属会话，创建回执同时冻结起点、来源及原映射；也可从同一聊天的可复用历史会话分支。
已核对的 OpenCode v2 返回带 `fork.sessionID` 来源关系的独立根会话，可以作为桥接映射继续执行 QQ 任务。
创建后自动切换，原会话保留；用“切换分支”可返回原会话或其他分支。
空会话无法 fork，旧版缺少接口时明确提示。接口见 [OpenCode API](https://dev.opencode.ai/v2/docs/api)。

分支复制聊天上下文，不复制共享工作目录或回滚文件。历史 QQ 任务仍引用原会话，聊天记录继续按真实任务归档。
新分支会清除复制的旧任务身份，恢复适用的桥接权限；群共享分支不保留旧管理员任务的默认授权。
私人群聊独立会话及其分支不能用于群共享映射，普通子任务也不会被当作可切换分支。

创建和切换校验管理员登录、CSRF、当前映射、聊天归属、工作目录、未完成任务、执行树与待处理请求。
创建期间若新任务到达或映射发生变化，保留已创建分支并提示尚未切换，不覆盖新映射；稍后可自行选择该分支。
原生 fork 不接受幂等请求编号，管理台在调用前持久化本次请求，拿到分支编号后保存回执。
网络超时或重启后的未确认请求不会再次创建；刷新可查看 OpenCode 已产生的分支。同一请求重放也不会撤销用户后来的手动切换。

## 模型与分支管理

会话顶部及完整会话提供模型设置，历史列表还可重命名、归档和恢复。
模型目录按机器人工作目录读取，只显示已启用模型及其真实 variant；“默认档位”沿用供应商默认行为。
选择只影响所选 OpenCode 会话的后续响应，不覆盖全局默认模型或其他会话。
群共享映射与主人群聊私密独立会话分别设置；新建的独立会话仍遵循原有默认模型配置。
模型切换要求没有未完成任务、活动执行树和待处理请求，并核对页面上的旧模型与旧映射；结果未确认时提示刷新核对。

名称最长 120 个字符。归档保留原始历史与 QQ 任务，默认在会话映射的历史列表中收起，
可通过“显示已归档”找到并恢复。当前映射不能归档，归档会话不能直接切换，须先恢复。
旧版群成员独立历史没有可管理的共享映射时，仍可浏览和导出，设置入口会明确提示。

## 会话导出

会话顶部、历史列表和完整会话均可下载导出文件：

- 正文 Markdown 或 JSON：只包含用户和助手的文字。
- 完整记录 JSON：包含当前会话仍保留的可见消息、工具与思考记录，并按管理台展示字段及共享规则脱敏。

后端读取 OpenCode 原生实验性导出接口并设置 `sanitize=true`，不创建模型任务。
额外去掉服务配置、权限配置、原始 native 包及非展示字段，不返回认证文件或附件原件。
单次导出上限 32 MiB，超限明确失败，不把部分记录冒充完整导出。子会话可分别导出。
查询及下载须管理员登录；不支持导出的 OpenCode 版本会明确提示。

## 插件与能力

侧栏“插件与能力”按机器人工作目录展示原生插件、MCP 连接、技能、命令、Agent 和搜索供应商。
原生插件与 MCP 分开显示；插件状态来自 OpenCode 注册目录，不把注册成功冒充每项工具调用验证。
搜索供应商标记实际配置的当前选择。每组接口独立降级，区分未注册与暂不可用，目录缓存 30 秒。
原生插件按注册名称分为 QQ 桥接、模型供应商、网页搜索、工具、提示词适配、核心与配置、其他插件，使用分类按钮切换并显示数量。
自动刷新时数据未变化只更新时间；目录变化时保留分类、各列表的可见项目位置及页面滚动位置，手动刷新也保留阅读位置。
仅返回名称、简介、类型、版本、状态等白名单字段，不返回插件 options、错误原文、技能全文、Agent 系统提示或模型认证配置。
该页只有查询入口，不更新插件、执行命令或修改配置。

## 服务重启

“系统管理 → 重启服务”显示当前待处理任务及等待交互数量，再请求 systemd 重启 `qqbot.service`。按钮不重启 OpenCode、NapCat、GSCore、PostgreSQL 或代理。

HTTP 202 仅表示请求已受理。页面会等待新的启动标识，确认后才显示已重启；失败或未确认时展示实际状态。队列和会话不清空，恢复遵循原有机制，发送不确定状态不盲目重发。

## 部署

`.env` 中启用：

```dotenv
WEBUI_ENABLED=true
WEBUI_HOST=127.0.0.1
WEBUI_PORT=8093
WEBUI_PUBLIC_URL=https://bot.example.com
```

核对 `deploy/qqbot-webui.nginx.conf` 中的域名、证书和端口，安装为独立 Nginx 配置。发布前检查任务、发送和记忆队列；不清空它们。通过测试后重启桥接，检查服务及连接就绪，再验证 HTTPS 登录和只读接口。

```bash
set -e
install -m 644 deploy/qqbot-webui.nginx.conf /etc/nginx/conf.d/qqbot-webui.conf
nginx -t
systemctl reload nginx
systemctl restart qqbot.service
```

桥接数据库和记忆数据库的浏览查询使用 SQLite `mode=ro` 连接，不构造 `Store` 或 `MemoryStore`，防止浏览操作触发迁移或发送恢复。浏览 OpenCode 使用独立客户端对象，不修改工作线程客户端的连接状态，也不创建模型任务。管理动作由独立的管理台账号授权，当前不提供普通 QQ 用户登录。

前端入口为 `webui_static/console.html`，通过同源 ES modules 加载 `console.js`。
会话和知识库页面分别在 `console-conversations.js`、`console-knowledge.js` 中管理自己的状态。
上下文展示与压缩交互由 `console-context.js` 管理，后端入口在 `webui_context.py`。
会话 fork、模型及属性管理由 `webui_sessions.py` 负责，创建回执保存在 `webui_auth.py`。
导出和能力目录分别由 `webui_export.py`、`webui_capabilities.py` 提供；会话设置交互复用 `console-context.js`。
页面切换、搜索和分页会丢弃过期的异步结果。发布时保持 HTML、模块资源和后端静态白名单
一致；修改 Python 路由后需重启桥接。浏览器刷新即可加载新入口，无需清空聊天记录。
