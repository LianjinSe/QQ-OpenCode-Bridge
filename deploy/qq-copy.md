# 助手：桥接回复文案


适用于 QQ→OpenCode 桥接服务。`{编号}`、`{数量}` 等为动态内容。编号、命令、资源路径和表单题目保留原始含义；服务日志和数据库保留原始诊断信息。


全部用户使用自然、友好的普通聊天口吻，不按固定 QQ 绑定恋爱关系或私人称呼。排队、保存、遗忘及交付状态必须准确；模型回复遵循独立工作目录的通用运行指引。


## 消息接收


| 情况 | 回复 |
| --- | --- |
| 读取引用消息失败 | 欸，你回复的那条消息我没读到呀，请确认引用的是当前聊天里的消息，或重发文字、图片、视频、音频、文件或合并转发，然后回复那条消息告诉我要做什么吧~ |
| 分享卡片无可用网页链接 | 这张分享卡片里没找到可用的网页链接，把链接直接发给我吧。 |
| 合并转发记录超限或循环嵌套 | 这份聊天记录太长或嵌套太多啦，拆成几个合并转发卡片，再分别回复我说明任务吧~ |
| 回传附件准备失败 | 这次的附件没能准备好发回来，文件还没交付。可以让我检查后重新发一次呀。 |
| 回传附件发送失败 | 有附件这次没能发成功，完整结果还没交付。可以让我检查后重新发一次呀。 |
| 回传附件发送结果不确定 | 有附件的发送结果还没确认，我先不重复发啦。你看看聊天里有没有收到，再决定是否重发呀。 |
| 回传附件全部确认发送成功 | 保留模型原本的回复，不额外追加固定成功提示。 |
| 附件数量或大小超限 | 这次的附件数量或总大小超限啦，少发一点或压小一点，再交给我吧~ |
| 队列已满，消息没有入队 | 欸？等一下等一下，我现在有点太忙了，思考不过来啦~<br>这条还没排进去哦，等我忙完一点再发，或用 /cancel 取消自己的任务（超级管理员可取消本群全部任务）。 |
| 新消息已排队 | 收到啦，我先把上一件事忙完，这条已经替你排好队啦~ |
| 同一私聊的新消息已接收为当前执行的补充 | 静默接收，不额外回复固定提示。 |

私聊执行期间的新普通消息采用 OpenCode `steer`，后续步骤读取补充；群聊沿用排队提示。
其他聊天或执行尚未开始时继续排队，执行已结束、正在交付时作为下一轮任务。


## /help

按请求所在的聊天类型选择文案；私聊只展示私聊用法，群聊只展示群聊用法。

### 私聊

```text
查资料、写代码、看图片或文件，都可以直接发给我呀~
我正在处理时，你补发的消息会一起接着看呀。
/status 看看我忙到哪啦；/cancel 停止任务并清空这个聊天的队列；/new 换个新话题。
/approve <编号> 批准这一次操作；/reject <编号> 不做这一步；/answer <编号> <回答>。
发图片时，记得一起写上要我做什么，也可以回复自己那条图片消息告诉我。
文件先发给我，再回复自己那条文件消息，告诉我要做什么呀。单独发文件时我会等你说明哦。
合并转发也先发给我，再回复自己那条卡片写上说明，我会把聊天记录一起读进去呀。
```

### 群聊

```text
本群共享聊天上下文，@我在消息的任何位置都可以呀~
/status 查看群任务；/cancel 取消自己的任务，超级管理员可取消全群任务。
/new 仅超级管理员可在群任务和交付完成后使用，开始新上下文。
/approve <编号> 批准一次；/reject <编号> 拒绝；/answer <编号> <回答> 回答自己的问题。
/trace <消息ID> 由超级管理员在本群 @我查询消息处理记录。
普通成员改文件需本群超级管理员批准，管理员本人发起的任务自动授权。
回复同群文字、图片、文件或转发卡片并 @我即可；不写说明时按“看看这个”处理。
直接发送文件或转发卡片后，需要回复那条消息再 @我；单独 @我且没有引用时不创建任务。
```

## 个人记忆

文案集中在 `qqbot/messages.py` 的 `MEMORY_COPY`。称呼只按真实 QQ 和当前聊天类型选择，不随管理员或记忆所有者配置转移。保存、遗忘、查询和日记分别提示处理进度，只有操作实际成功才确认完成；回查的原话和已有记忆内容保持原文。`/memories` 在每条前加 `[你]`、`[棠溪]` 或 `[共同经历]` 标明内容主体。

| 情况 | 回复示例 |
| --- | --- |
| 记住请求已排队 | 等我把这件事记好呀，记好了就告诉你~ |
| 私聊确认已记住 | 记住啦，换个新话题也还记得的~ |
| 群聊确认已记住 | 记住啦，换个新话题也还记得的~ |
| 查找聊天原话 | 我找找当时怎么说的，等我一下呀~ |
| 日记等待整理 | 这天的日记已经排队啦，晚点用 /diary {日期} 来看看呀~ |
| 私聊确认已遗忘 | 这件事我放下啦，相关的记忆和日记一共清掉了 {数量} 条，不会再从旧聊天里记回来。 |
| 保留聊天原文 | 之前的聊天原文还留着，但不会再拿这些内容来回忆或整理了。 |
| 同时清除聊天原文 | 相关的聊天原文也一起清掉啦。 |
| 私聊保存失败 | 这次还没记好呢，先别当作已经保存啦。晚点用 /memory retry，我再试一次。 |
| 私聊遗忘未完成 | 这次还没处理完，先别当作已经全部忘掉啦。晚点用 /memory retry，我接着处理。 |

个人记忆启用者的 `/help` 追加：

```text
想让我记住的事，可以直接说“记住……”，也可以用 /remember 内容呀。
/forget 内容 让我忘掉那件事；/memories 看看我记着什么；/diary 日期 看那天的日记。
/memory history 关键词 找聊天原话；/memory 看看记忆的情况。
/memory retry 让我再试一次没完成的整理；/memory purge 关键词 忘掉相关记忆，也清掉相关聊天原文。
用 /new 换个话题，之前记住的事也还在哦。
```

## /status

```text
我这边现在是这样呀：
消息连接：{在线/离线}；任务连接：{已连上/正在等连接}
这个聊天还有 {数量} 件事没处理完；最近一件：{状态}
任务发起人：{QQ 号列表或无}
等点头或回答：{等批准 [编号] / 等回答 [编号] / 没有啦}
你的身份：{超级管理员/授权用户}；操作权限：{权限说明}
```

| 状态 | 展示文案 |
| --- | --- |
| queued | 排着队呢 |
| preparing | 正在收好附件 |
| submitting | 正在开始这件事 |
| running | 正在忙这件事 |
| waiting | 等点头或回答呢 |
| cancelling | 正在停下来 |
| reply_ready | 回复写好啦，正准备发 |
| delivering | 图片或文件正往聊天里发呢 |
| done | 做完啦 |
| failed | 这次没做完 |
| cancelled | 已经停下来啦 |
| send_uncertain | 回复有没有送到还没确认 |
| send_failed | 回复没发成功 |
| unknown | 状态还没确认 |
| no job | 还没接到任务 |


权限说明：

- 按常规规则，需要批准的操作会先问你
- 你在当前聊天里已经默认授权所有操作啦
- 只读操作我会直接做，改文件或还没确认只读的操作要本群超级管理员点头

## 请求授权

```text
我可以修改这些文件吗？ [{编号}]
{资源列表}
/approve {编号} 本次批准
/reject {编号} 拒绝
```


已知操作使用下表中的描述；未知操作保留工具名，写为“我可以调用 {操作名} 完成这一步吗？”；操作名缺失时写为“我可以执行下面这一步吗？”。

| 操作 | 问句中的描述 |
| --- | --- |
| read | 读取这些文件 |
| glob | 查找这些文件 |
| grep | 搜索这些文件里的内容 |
| edit | 修改这些文件 |
| write | 写入这些文件 |
| patch | 修改这些文件 |
| apply_patch | 修改这些文件 |
| delete | 删除这些文件 |
| remove | 删除这些文件 |
| shell | 执行下面的命令 |
| external_directory | 访问这个目录 |
| websearch | 搜索这些资料 |
| webfetch | 读取这个网页 |
| skill | 使用这个技能 |
| execute | 执行这一步操作 |
| subagent | 启动这个子任务 |


群内有超级管理员时，在请求前加：

```text
这一步要请本群的超级管理员点个头呀。
发起人 QQ：{QQ号}
```

在请求后加：

```text
管理员直接在本群回上面的指令就行啦。
```


群内未配置超级管理员时，在请求前加：

```text
群里还没配置超级管理员，这一步暂时没法批准呀。
```


## 表单提问

```text
我还想确认一下呀 [{编号}]：{表单标题}
{字段标题，没有标题时保留字段标识}
{字段说明，如有}
1. {选项名称，如有}
2. {选项名称，如有}
{字段类型提示，如有}
/answer {编号} <回答>
```

| 情况 | 字段提示 |
| --- | --- |
| 外部或隐藏字段 | 这一项需要到 OpenCode 界面填一下呀，填好我就能接着做啦~ |
| 多选 | 可以用逗号分隔多个选项编号哦。 |
| 布尔值 | 回我 是 / 否 就行啦。 |
| 数字 | 这一项填数字就行啦。 |
| 非必填 | 这一项可以跳过：/answer {编号} /skip |
| 回答收集完成的备用文案 | 你的回答都记下啦，我正在提交~ |


外部或隐藏字段不附选项和 /answer 指令，按提示到 OpenCode 界面填写。


## 表单回答校验


- 这个选项没对上呀，回我一个有效的选项编号或名称就行啦~
- 这个问题的回答已经收齐啦，不用再填一次哦~
- 这一项得在 OpenCode 界面填呀，填好我再继续~
- 这一项是必填的呀，不能跳过，给我一个回答吧~
- 这条回答有点太短啦，再多写一点呀~
- 这条回答有点太长啦，稍微缩短一点再发我吧~
- 这条回答的格式没对上呀，照着题目要求再填一次吧~
- 这一项的格式规则我没法解析呀，到 OpenCode 界面填一下吧~
- 这个数字没读懂呀，回我一个有效的数字吧~
- 这个数字超出允许范围啦，照着题目里的范围再填一次吧~
- 这一项回我 是 / 否 就行啦~
- 多选的编号没读对呀，用逗号分隔选项编号再发一次吧~
- 选项的数量没对上题目要求呀，增减一下再发我吧~
- 这一类问题需要在 OpenCode 界面回答呀，填好我再继续~


## 任务结果与超时


| 情况 | 回复 |
| --- | --- |
| 正常完成 | OpenCode 最后一条助手消息里的文字，原样转发。 |
| 失败原因未识别 | 唔，这次中途卡住了，还没做完呀。可以先看看服务日志或 OpenCode 里的这轮记录，再试一次~ |
| 任务被中断 | 这件事已经停下来啦~ |
| 完成但没有文字结果 | 这次已经处理完啦，不过没有文字回复可以发给你呀。 |
| 等待授权或回答超时，确认停止后 | 等你点头或回答等得有点久啦，这件事已经停下来，要继续的话再发我一次吧~ |
| 执行超时，确认停止后 | 这件事执行超时啦，我已经停下来了，等会儿再试，或把任务拆小一点交给我吧~ |

## 动态异常与停止确认

其他 HTTP 请求错误：

```text
唔，这一步请求没成功，我还没做完呀。看看服务日志再试吧~
错误信息：{方法} {接口类别}（HTTP {状态码}）
```


未识别的异常：

```text
唔，这次遇到一个还没识别的错误，没能做完呀。
错误信息：{原始错误信息}
```


执行中出现上述错误，确认任务已经停止后，额外加一句：

